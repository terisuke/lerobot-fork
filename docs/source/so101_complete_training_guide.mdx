# SO-101完全ガイド: テレオペレーションからトレーニングまで

このガイドでは、SO-101ロボットアームを使って、テレオペレーションができる状態から始めて、2台のwebカメラでデータセットを作成し、ACTポリシーをトレーニングして評価するまでの完全な流れを初心者向けに説明します。

> [!TIP]
> **新しい開発者向け**: このガイドには[開発者向けクイックスタート](#開発者向けクイックスタート)セクションが含まれています。迅速にセットアップを開始したい場合は、このセクションを参照してください。

## はじめに

このガイドを完了すると、以下のことができるようになります：

1. 2台のwebカメラをセットアップする
2. テレオペレーションでロボットを操作しながらデータセットを記録する
3. 記録したデータセットを確認する
4. ACTポリシーをトレーニングする
5. トレーニングしたポリシーでロボットを評価する

### 前提条件

このガイドを始める前に、以下が完了している必要があります：

- ✅ SO-101ロボットアームの組み立てが完了している
- ✅ モーターのID設定とキャリブレーションが完了している（[SO-101セットアップガイド](./so101)を参照）
- ✅ テレオペレーションが正常に動作している
- ✅ LeRobotがインストールされている（[インストールガイド](./installation)を参照）
- ✅ Hugging Faceアカウントを作成し、`huggingface-cli login`でログインしている

### 必要なハードウェア

- SO-101 Follower Arm（操作されるロボット）
- SO-101 Leader Arm（テレオペレーション用のコントローラー）
- USB webカメラ 2台（推奨：640x480 @ 30fps以上）
- USBポート 4つ（Follower、Leader、カメラ2台）

> [!TIP]
> カメラの数は1台でも動作しますが、2台のカメラ（例：正面カメラと横カメラ）を使用することで、モデルの性能が向上します。公式ドキュメントや実践的な報告では、正面と横の組み合わせが精度向上に効果的とされています。

### よくある問題と事前準備

このガイドを進める際に、以下の問題が発生する可能性があります。事前に確認しておくとスムーズに進められます：

- **macOSでのOpenMPエラー**: `KMP_DUPLICATE_LIB_OK=TRUE`環境変数の設定が必要な場合があります（[詳細](#問題-omp-error-15-initializing-libompdylib-but-found-libompdylib-already-initialized)）
- **FFmpegライブラリエラー**: `--dataset.video_backend=pyav`を指定することで回避できます（[詳細](#問題-runtimeerror-could-not-load-libtorchcodecトレーニング中)）
- **カメラ接続エラー**: カメラの解像度やFPS設定を調整する必要がある場合があります（[詳細](#問題パターン1-runtimeerror-opencvcamera0-read-failed-statusfalse)）
- **トレーニング出力ディレクトリの競合**: 既存のディレクトリがある場合、自動的にタイムスタンプが追加されます（[詳細](#トレーニング出力ディレクトリの管理)）

これらの問題は、このガイドの[トラブルシューティング](#トラブルシューティング)セクションで詳しく説明しています。

## ステップ1: カメラのセットアップ

### 1.1 カメラの検出

まず、接続されているカメラを確認します：

```bash
lerobot-find-cameras opencv
```

出力例：

```

Camera #0:
  Name: OpenCV Camera @ 0
  Type: OpenCV
  Id: 0
  Backend api: AVFOUNDATION
  Default stream profile:
    Format: 16.0
    Width: 1920
    Height: 1080
    Fps: 15.0
--------------------
Camera #1:
  Name: OpenCV Camera @ 1
  Type: OpenCV
  Id: 1
  Backend api: AVFOUNDATION
  Default stream profile:
    Format: 16.0
    Width: 1920
    Height: 1080
    Fps: 15.0
--------------------
```

この例では、カメラ0とカメラ1が検出されています。これらのIDをメモしておきます。

> [!WARNING]
> カメラのIDは、コンピュータを再起動したり、カメラを再接続したりすると変わる可能性があります。データセット記録の前に、必ずカメラIDを確認してください。

### 1.2 カメラの配置

2台のカメラを以下のように配置することを推奨します：

- **正面カメラ（front）**: ロボットの正面から作業エリアを見る。物体の形状や位置を正確に捉えるのに適しています
- **横カメラ（side）**: 作業エリアの横（約45度の角度）から見る。深度情報の取得に優れ、物体の3次元構造を理解しやすくなります

この配置により、モデルは異なる視点からの視覚情報を学習でき、物体の形状、位置、深度をより正確に理解できるようになります。公式ドキュメントや実践的な報告では、この正面と横の組み合わせが精度向上に効果的とされています。

## ステップ2: データセットの記録

### 2.1 データセット記録の準備

データセットを記録する前に、以下を確認してください：

1. **Hugging Face環境変数の設定**: まず、Hugging Faceのユーザー名を環境変数に設定します：

   ```bash
   export HF_USER=$(hf auth whoami | head -n 1 | sed 's/user: //')
   echo $HF_USER
   ```

   これで`HF_USER`環境変数が設定されます。ターミナルを閉じると設定が消えるため、毎回設定するか、`~/.zshrc`や`~/.bashrc`に追加してください。

2. **USBポートの接続**: Follower、Leader、カメラ2台がすべて接続されている
3. **カメラIDの確認**: `lerobot-find-cameras opencv`でカメラIDを確認
4. **ポート番号の確認**: `lerobot-find-port`でFollowerとLeaderのポートを確認

   ```bash
   lerobot-find-port
   ```

   このコマンドを実行すると、接続されているポートのリストが表示されます。FollowerとLeaderのUSBケーブルを順番に抜いて、どのポートがどちらに対応するかを確認してください。

   > [!IMPORTANT]
   > FollowerとLeaderのポートを間違えると、エラーが発生します。必ず確認してください。

### 2.2 データセット記録コマンド

以下のコマンドでデータセットを記録します：

```bash
# まず、HF_USER環境変数を設定（毎回実行するか、~/.zshrcに追加）
# 方法1: hfコマンドから取得（推奨）
export HF_USER=$(hf auth whoami 2>&1 | grep -oP 'user:\s*\K\S+' | tr -d '[:space:]')
# 方法2: 直接ユーザー名を指定（環境変数が展開されない場合）
# export HF_USER="Terisuke"
echo "HF_USER is set to: '${HF_USER}'"  # 確認用（クォートで囲むと特殊文字が見える）

# データセット記録コマンド（同じシェルで実行）
# 注意: width、height、fpsの指定が必須です。カメラがサポートしている解像度とFPSを使用してください
# 注意: ポート番号は、lerobot-find-portで確認した実際のポートに置き換えてください

# 完全版コマンド（ポート番号を実際の値に置き換えてください）
lerobot-record \
    --robot.type=so101_follower \
    --robot.port=/dev/tty.wchusbserial5AB90691861 \
    --robot.id=my_awesome_follower_arm \
    --robot.cameras='{"front": {"type": "opencv", "index_or_path": 0, "width": 1280, "height": 960, "fps": 25}, "side": {"type": "opencv", "index_or_path": 1, "width": 640, "height": 480, "fps": 30}}' \
    --teleop.type=so101_leader \
    --teleop.port=/dev/tty.wchusbserial5AB90684961 \
    --teleop.id=my_awesome_leader_arm \
    --display_data=true \
    --dataset.repo_id=Terisuke/my_so101_dataset \
    --dataset.num_episodes=50 \
    --dataset.single_task="Put a white cat next to a black cat"
```

> [!WARNING]
> **ポート番号の確認**:
>
> - ポート番号は、`lerobot-find-port`コマンドで確認してください
> - FollowerとLeaderのポートが逆になっていると、エラーが発生します
> - 一般的に、Followerは`/dev/tty.wchusbserial5AB90691861`、Leaderは`/dev/tty.wchusbserial5AB90684961`ですが、環境によって異なる場合があります

> [!IMPORTANT]
> **カメラ設定の必須項目**:
>
> - ロボットで使用するカメラには、`width`、`height`、`fps`の指定が**必須**です
> - カメラがサポートしていない解像度やFPSを指定すると、エラーが発生する可能性があります
> - カメラのサポート解像度を確認するには、`lerobot-find-cameras opencv`を実行してください
> - カメラ0が読み込めない場合は、カメラ1と2を試してください（`index_or_path: 1`と`index_or_path: 2`）
> - 一般的に、640x480@30fpsは多くのカメラでサポートされています

> [!WARNING]
> **重要**: `HF_USER`環境変数は、`lerobot-record`コマンドを実行する**同じシェル**で設定する必要があります。新しいターミナルウィンドウやタブでコマンドを実行する場合は、そのシェルでも環境変数を設定してください。
>
> 環境変数が設定されていない場合、以下のエラーが発生します：
>
> - `OSError: [Errno 30] Read-only file system: '/my_so101_dataset'`（絶対パスとして解釈される）
> - `yaml.reader.ReaderError: unacceptable character`（特殊文字エラー）

> [!NOTE]
>
> - `front`カメラは720p（1280x720）@30fps、`fourcc="MJPG"`を指定して高FPSを確保
> - `side`カメラは640x480@30fps（必要に応じて調整可能）
> - 環境変数の代わりに、直接ユーザー名を指定することもできます：`--dataset.repo_id=Terisuke/my_so101_dataset`

**パラメータの説明**：

- `--robot.type`: ロボットのタイプ（`so101_follower`）
- `--robot.port`: FollowerアームのUSBポート（`lerobot-find-port`で確認）
- `--robot.id`: ロボットの一意のID（キャリブレーションファイルに関連付けられる）
- `--robot.cameras`: カメラ設定の辞書
  - `front`: 正面カメラ（ID 0）
  - `side`: 横カメラ（ID 1）
  - `width`, `height`, `fps`: 解像度とフレームレート
- `--teleop.type`: テレオペレーターのタイプ（`so101_leader`）
- `--teleop.port`: LeaderアームのUSBポート
- `--teleop.id`: Leaderアームの一意のID
- `--display_data`: リアルタイムでカメラ映像を表示するか（`true`/`false`）
- `--dataset.repo_id`: Hugging Face HubのデータセットリポジトリID
- `--dataset.num_episodes`: 記録するエピソード数（推奨：50以上）
- `--dataset.single_task`: タスクの説明

> [!TIP]
> データセットの品質を向上させるために：
>
> - エピソード数は50以上を推奨
> - オブジェクトの位置を変えて多様性を持たせる
> - 一貫したグリッピング方法を保つ
> - 各エピソードは約60秒程度を目安にする

### 2.3 データセット記録の操作

記録中は以下のキーボード操作が可能です：

- **右矢印キー（→）**: 現在のエピソードを完了して保存（またはリセット時間をスキップ）
- **左矢印キー（←）**: 現在のエピソードを破棄して再記録
- **Escキー**: 記録を停止

**エピソード記録の流れ**:

1. **エピソード記録**: 各エピソードは最大60秒（`--dataset.episode_time_s`で変更可能）記録されます
   - 右矢印キーを押すと、エピソードを早期に完了して保存できます
   - 右矢印キーを押さない場合、60秒経過すると自動的にエピソードが完了します

2. **環境リセット**: エピソード保存後、環境をリセットする時間が最大60秒（`--dataset.reset_time_s`で変更可能）与えられます
   - 右矢印キーを押すと、リセット時間をスキップして次のエピソードに進みます
   - 右矢印キーを押さない場合、60秒経過すると自動的に次のエピソードに進みます

3. **次のエピソード**: 上記の流れが`--dataset.num_episodes`で指定した回数（デフォルト50回）繰り返されます

> [!TIP]
> **効率的な記録方法**:
>
> - エピソードが完了したら、すぐに右矢印キーを押して保存します
> - 環境をリセットしたら、すぐに右矢印キーを押して次のエピソードに進みます
> - 50エピソードを記録する場合、合計で約100回（エピソード完了50回 + リセットスキップ49回）右矢印キーを押すことになります
> - ただし、右矢印キーを押さなくても、時間が経過すれば自動的に次のステップに進みます

### 2.4 データセット記録の完了

すべてのエピソードの記録が完了すると、データセットが自動的にHugging Face Hubにアップロードされます。アップロードには時間がかかる場合があります。

## ステップ4: ポリシーのトレーニング（ACT）

### 4.1 基本的なトレーニングコマンド

記録したデータセットを使ってACTポリシーをトレーニングします：

```bash
# Hugging Faceユーザー名を設定（必要に応じて）
export HF_USER="Terisuke"

# 基本的なトレーニングコマンド
lerobot-train \
    --dataset.repo_id=Terisuke/my_so101_dataset \
    --policy.type=act \
    --output_dir=outputs/train/act_my_so101_dataset \
    --job_name=act_my_so101_dataset \
    --policy.device=mps \
    --wandb.enable=false \
    --policy.repo_id=Terisuke/my_act_policy
```

**パラメータの説明**：

- `--dataset.repo_id`: トレーニングに使用するデータセットのID
- `--policy.type`: ポリシーのタイプ（`act`）
- `--output_dir`: チェックポイントの保存先
- `--job_name`: ジョブ名（ログに表示される）
- `--policy.device`: 使用するデバイス（`cuda`、`mps`、`cpu`）
  - `cuda`: NVIDIA GPU
  - `mps`: Apple Silicon（M1/M2/M3/M4 Mac）
  - `cpu`: CPUのみ
- `--wandb.enable`: Weights & Biasesを使用するか（`true`/`false`）
- `--policy.repo_id`: トレーニングしたポリシーをアップロードするHugging Face HubのリポジトリID

> [!TIP]
> Weights & Biasesを使用する場合は、事前に`wandb login`でログインしてください。

### 4.2 macOS向けの最適化設定（M4 Maxなど高メモリ環境）

M4 Max（128GBメモリなど）のような高メモリ環境では、以下の最適化設定を使用することで、トレーニング速度を大幅に向上させることができます：

```bash
# OpenMPエラーを回避するための環境変数設定
export KMP_DUPLICATE_LIB_OK=TRUE

# 最適化されたトレーニングコマンド
lerobot-train \
    --dataset.repo_id=Terisuke/my_so101_dataset \
    --dataset.video_backend=pyav \
    --policy.type=act \
    --output_dir=outputs/train/act_my_so101_dataset \
    --job_name=act_my_so101_dataset \
    --policy.device=mps \
    --wandb.enable=false \
    --policy.repo_id=Terisuke/my_act_policy \
    --batch_size=32 \
    --num_workers=8 \
    --policy.optimizer_lr=3e-5 \
    --save_freq_minor=5000
```

**最適化パラメータの説明**：

- `KMP_DUPLICATE_LIB_OK=TRUE`: OpenMPライブラリの重複エラーを回避（macOSのconda環境で必要）
- `--dataset.video_backend=pyav`: ビデオデコーディングに`pyav`バックエンドを使用（FFmpegライブラリの問題を回避）
- `--batch_size=32`: デフォルト8から32に増加（メモリが許す範囲で調整可能）
- `--num_workers=8`: データローディングの並列化を強化（デフォルト4から増加）
- `--policy.optimizer_lr=3e-5`: 学習率を調整（バッチサイズを増やす場合は学習率も調整）
- `--save_freq_minor=5000`: 軽量チェックポイント（モデルのみ）を5,000ステップごとに保存（推奨）

> [!TIP]
> **バッチサイズの調整**:
>
> - メモリが十分な場合: `--batch_size=32`または`--batch_size=64`（推奨）
> - メモリが限られている場合: `--batch_size=16`
> - メモリ不足エラーが発生した場合: `--batch_size=8`（デフォルト）に戻す

> [!TIP]
> **num_workersの調整**:
>
> - CPUコア数が多い場合: `--num_workers=8`または`--num_workers=12`
> - 問題が発生する場合: `--num_workers=4`に減らす

> [!TIP]
> **チェックポイント保存の設定**:
>
> - `--save_freq=20000`: 完全なチェックポイント（モデル+最適化状態）を20,000ステップごとに保存（デフォルト）
> - `--save_freq_minor=5000`: 軽量チェックポイント（モデルのみ）を5,000ステップごとに保存（推奨）
> - 軽量チェックポイントは再開には使用できませんが、モデルの評価には使用できます
> - Ctrl+Cで停止した場合、自動的にチェックポイントが保存されます

### 4.3 トレーニング時間

ACTのトレーニングは通常、以下の時間がかかります：

- **100kステップ**: 約1-3時間（デバイスとバッチサイズによる）
- **デフォルトのバッチサイズ**: 8（GPUメモリに応じて調整可能）
- **最適化設定（batch_size=64）**: 約30分-1時間（M4 Maxの場合）

トレーニング中は、`outputs/train/act_my_so101_dataset/checkpoints/`にチェックポイントが保存されます。

### 4.4 トレーニングの進行状況を確認

トレーニングの進行状況を確認するには：

```bash
# チェックポイントの確認
ls -lh outputs/train/act_my_so101_dataset/checkpoints/

# ログファイルの確認
tail -f outputs/train/act_my_so101_dataset/logs/*.log
```

### 4.5 トレーニング出力ディレクトリの管理

#### 自動的な名前更新機能

既存の出力ディレクトリがある場合、システムは自動的にタイムスタンプを追加して新しいディレクトリ名を生成します。これにより、既存のチェックポイントを削除せずに新しいトレーニングを開始できます。

**動作例**:

```bash
# 既存のディレクトリ: outputs/train/act_my_so101_dataset
# 新しいトレーニングを開始すると:
# → outputs/train/act_my_so101_dataset_20241203_101530
```

**警告メッセージ**:

既存のディレクトリが検出された場合、以下のような警告が表示されます：

```
WARNING: Output directory outputs/train/act_my_so101_dataset already exists. 
Automatically renaming to outputs/train/act_my_so101_dataset_20241203_101530 to avoid overwriting. 
To resume training, use --resume=true
```

#### トレーニングの再開

既存のトレーニングを再開する場合は、`--resume=true`を使用してください：

```bash
export KMP_DUPLICATE_LIB_OK=TRUE

lerobot-train \
    --dataset.repo_id=Terisuke/my_so101_dataset \
    --dataset.video_backend=pyav \
    --policy.type=act \
    --output_dir=outputs/train/act_my_so101_dataset \
    --job_name=act_my_so101_dataset \
    --policy.device=mps \
    --wandb.enable=false \
    --policy.repo_id=Terisuke/my_act_policy \
    --batch_size=32 \
    --num_workers=8 \
    --policy.optimizer_lr=3e-5 \
    --save_freq=20000 \
    --save_freq_minor=5000 \
    --resume=true \
    --policy.push_to_hub=false
```

> [!NOTE]
> - `--resume=true`を使用する場合、既存のディレクトリがそのまま使用されます
> - 自動的な名前更新は行われません
> - 最新のチェックポイントからトレーニングが再開されます

#### チェックポイントの管理

- **完全なチェックポイント**: `save_freq`（デフォルト: 20,000ステップ）ごとに保存。モデル、オプティマイザー、スケジューラーの状態を含む
- **軽量チェックポイント**: `save_freq_minor`（設定した場合）ごとに保存。モデルの重みのみを含む
- **Ctrl+Cでの自動保存**: トレーニングを中断した場合、自動的にチェックポイントが保存されます

## トラブルシューティング

### カメラ関連の問題

#### 問題: `TimeoutError: Timed out waiting for frame from camera`

**原因**: カメラからのフレーム取得がタイムアウトしている

**解決策**:

- 仮想webカメラ（例：AndroidのCamo）を使用している場合は、直接USB接続のwebカメラに切り替える
- カメラの解像度やFPSを下げる（例：640x480 @ 15fps）
- USBケーブルを確認し、USB 3.0ポートを使用する

#### 問題: カメラが検出されない

**解決策**:

- `lerobot-find-cameras opencv`を再実行してカメラIDを確認
- カメラを再接続する
- 他のアプリケーションがカメラを使用していないか確認

### キャリブレーション関連の問題

#### 問題: ロボットアームの動きが鈍い、またはキャリブレーションをやり直したい

**解決策1: プロンプトで再キャリブレーションを選択**

`lerobot-calibrate`コマンドを実行すると、既存のキャリブレーションファイルがある場合、以下のプロンプトが表示されます：

```
Press ENTER to use provided calibration file associated with the id my_awesome_leader_arm, or type 'c' and press ENTER to run calibration:
```

このプロンプトで**`c`と入力してEnterを押す**と、新しいキャリブレーションが実行されます。

**解決策2: キャリブレーションファイルを削除してから再実行**

キャリブレーションファイルを削除してから、`lerobot-calibrate`コマンドを再実行します：

```bash
# キャリブレーションファイルの場所を確認
# デフォルト: ~/.cache/huggingface/lerobot/calibration/teleoperators/so101_leader/{id}.json

# Leaderアームのキャリブレーションファイルを削除
rm ~/.cache/huggingface/lerobot/calibration/teleoperators/so101_leader/my_awesome_leader_arm.json

# Followerアームのキャリブレーションファイルを削除（必要に応じて）
rm ~/.cache/huggingface/lerobot/calibration/robots/so101_follower/my_awesome_follower_arm.json

# キャリブレーションを再実行
lerobot-calibrate \
    --teleop.type=so101_leader \
    --teleop.port=/dev/tty.wchusbserial5AB90684961 \
    --teleop.id=my_awesome_leader_arm
```

**キャリブレーション手順**:

1. **中間位置に移動**: すべての関節を可動範囲の中間位置に移動し、Enterを押します
2. **全可動範囲を動かす**: 各関節を順番に全可動範囲で動かします
3. **記録を停止**: すべての関節を動かし終えたら、Enterを押して記録を停止します

> [!TIP]
> キャリブレーションは、ロボットアームの動きの精度に大きく影響します。動きが鈍い、または不正確な場合は、キャリブレーションをやり直すことをお勧めします。

### ロボット関連の問題

#### 問題: `RuntimeError: [RxPacketError] Input voltage error!`

**原因**: モーターへの電源供給が不十分、または電圧が適切でない

**解決策**:

1. **電源アダプターを確認**:
   - モーターに適切な電圧（通常7.4V〜12V）が供給されているか確認
   - 電源アダプターの出力電圧と電流容量を確認
   - 推奨: 7.4V 2A以上、または12V 2A以上の電源アダプター

2. **USBケーブルを確認**:
   - USBケーブルがしっかり接続されているか確認
   - USB 3.0対応のケーブルを使用（データ転送が安定）
   - ケーブルを別のものに交換して試す

3. **モーターの接続を確認**:
   - モーターへの電源ケーブルがしっかり接続されているか確認
   - モーターバスの接続を確認
   - モーターのID設定が正しいか確認（`lerobot-setup-motors`で確認）

4. **電源を再起動**:
   - モーターの電源を一度切って、数秒待ってから再度投入
   - USBケーブルを抜いて再度接続

5. **ポートを確認**:
   - 正しいポートを使用しているか確認（`lerobot-find-port`で確認）
   - 他のアプリケーションが同じポートを使用していないか確認

> [!WARNING]
> 電圧エラーが続く場合、モーターやコントローラーボードの故障の可能性があります。電源アダプターの仕様を確認し、推奨電圧・電流範囲内で使用してください。

#### 問題: `ConnectionError: Failed to sync read 'Present_Position'`

**原因**: ロボットとの通信が不安定

**解決策**:

- `--display_data=false`に設定してリアルタイム表示を無効化（M1 Macで特に有効）
- USBケーブルを確認し、USB 3.0ポートを使用する
- ロボットの電源を確認する

#### 問題: アームが不安定に動く（ジッター）

**原因**: USB帯域幅の不足や処理能力の限界

**解決策**:

- カメラの数を1台に減らす（ただし、モデルの性能に影響する可能性がある）
- カメラの解像度やFPSを下げる
- `--display_data=false`に設定する

### カメラ接続の問題

カメラ関連の問題には、いくつかの決まったパターンがあります。以下の順序で対処することで、ほとんどの問題を解決できます。

#### 問題パターン1: `RuntimeError: OpenCVCamera(0) read failed (status=False)`

**症状**: カメラが読み込めない、またはフレーム取得に失敗する

**原因と解決策（順番に試してください）**:

1. **FOURCC設定の問題**:
   - `fourcc: "MJPG"`を削除して試す
   - カメラがMJPGをサポートしていない場合があります
   ```bash
   # MJPGを削除した設定
   --robot.cameras='{"front": {"type": "opencv", "index_or_path": 0, "width": 640, "height": 480, "fps": 30}, "side": {"type": "opencv", "index_or_path": 1, "width": 640, "height": 480, "fps": 30}}'
   ```

2. **解像度/FPS設定の問題**:
   - カメラがサポートしていない解像度やFPSを指定している可能性があります
   - 解像度を下げる（例：1280x960 → 640x480）
   - FPSを下げる（例：30fps → 15fps）
   ```bash
   # 低解像度・低FPS設定
   --robot.cameras='{"front": {"type": "opencv", "index_or_path": 0, "width": 640, "height": 480, "fps": 15}, "side": {"type": "opencv", "index_or_path": 1, "width": 640, "height": 480, "fps": 15}}'
   ```

3. **カメラリソースの解放問題**:
   - 前回のセッションが完全に終了していない可能性があります
   - 解決策:
     - 他のプロセスがカメラを使用していないか確認: `ps aux | grep lerobot`
     - カメラを物理的に再接続（USBケーブルを抜いて再度接続）
     - システムを再起動（macOSの場合、カメラリソースが適切に解放されない場合がある）

4. **カメラIDの変更**:
   - 再起動や再接続でカメラIDが変わっている可能性があります
   ```bash
   # カメラIDを再確認
   lerobot-find-cameras opencv
   ```
   - 出力されたカメラIDを使用してください

5. **macOS固有の問題**:
   - カメラの権限を確認（システム環境設定 > セキュリティとプライバシー > カメラ）
   - 他のアプリケーション（Zoom、Skype、Photo Boothなど）を閉じる
   - 仮想webカメラ（例：AndroidのCamo）を使用している場合は、直接USB接続のwebカメラに切り替える

#### 問題パターン2: `OpenCVCamera(0) failed to set fourcc=MJPG`

**症状**: MJPG形式の設定に失敗する警告が表示される

**原因**: カメラがMJPG形式をサポートしていない

**解決策**:
- 警告のみで動作する場合は問題ありません
- FPSが低い場合は`fourcc`を削除してください
- 高FPSが必要な場合は、カメラの仕様を確認してMJPGをサポートしているカメラを使用してください

#### 問題パターン3: カメラ設定変更後の読み取り失敗

**症状**: 解像度やFPSを設定した直後にカメラの読み取りが失敗する

**原因**: カメラの設定変更後にカメラが一時的に不安定になる

**解決策**:
- コードが自動的にカメラをリセットして再試行するようになっています
- それでも失敗する場合は、カメラを物理的に再接続してください

#### 推奨されるトラブルシューティング手順

カメラの問題が発生した場合、以下の順序で対処してください：

1. **カメラIDの確認**: `lerobot-find-cameras opencv`でカメラIDを確認
2. **FOURCCの削除**: `fourcc: "MJPG"`を削除して試す
3. **解像度/FPSの調整**: 640x480 @ 15fpsなどの低設定で試す
4. **カメラの再接続**: USBケーブルを抜いて再度接続
5. **プロセスの確認**: 他のプロセスがカメラを使用していないか確認（`ps aux | grep lerobot`）
6. **システムの再起動**: 上記で解決しない場合、システムを再起動

#### 問題: GPUメモリ不足

**解決策**:

- バッチサイズを減らす（`--batch_size=32`または`--batch_size=16`）
- 画像の解像度を下げる（データセット記録時に640x480を使用）
- より小さいモデルを使用する

#### 問題: トレーニングが遅い

**解決策**:

- **Apple Silicon（M1/M2/M3/M4）の場合**:
  - `--batch_size=64`に増やす（メモリが許す範囲で）
  - `--num_workers=12`に増やす（データローディングの並列化）
  - `--policy.optimizer_lr=3e-5`に調整（バッチサイズを増やす場合）
- **NVIDIA GPUの場合**:
  - GPUが正しく認識されているか確認（`nvidia-smi`または`torch.cuda.is_available()`）
  - バッチサイズを増やす（GPUメモリが許す範囲で）
- **共通**:
  - データセットをローカルにダウンロードして使用

#### 問題: 既存の出力ディレクトリがある場合のエラー

**症状**: `FileExistsError: Output directory ... already exists`

**原因**: 既存の出力ディレクトリがある場合、デフォルトではエラーが発生します

**解決策**:

1. **自動的な名前更新（推奨）**: 
   - システムが自動的にタイムスタンプを追加して新しいディレクトリ名を生成します
   - 既存のチェックポイントは保持されます
   - 警告メッセージが表示されますが、トレーニングは続行されます

2. **トレーニングの再開**:
   - `--resume=true`を使用して既存のトレーニングを再開
   ```bash
   lerobot-train \
       --output_dir=outputs/train/act_my_so101_dataset \
       --resume=true \
       ...
   ```

3. **手動でのディレクトリ名変更**:
   - `--output_dir`に別の名前を指定
   ```bash
   lerobot-train \
       --output_dir=outputs/train/act_my_so101_dataset_v2 \
       ...
   ```

> [!TIP]
> 自動的な名前更新機能により、既存のチェックポイントを削除せずに新しいトレーニングを開始できます。タイムスタンプは秒単位なので、同じ秒に複数のトレーニングを開始すると競合する可能性があります（稀）。

#### 問題: エピソード終了時に自動停止しない

**症状**: 評価時にエピソードが終了してもCtrl+Cを押さないと停止しない

**原因**: リセットフェーズでポリシーやテレオペレーターが提供されていない場合、タイムスタンプの更新がスキップされていた

**解決策**:
- コードが修正され、エピソード終了時に自動的に停止するようになりました
- エピソード時間（`episode_time_s`）が経過すると自動的に停止します
- リセット時間（`reset_time_s`）が経過すると自動的にリセットフェーズが終了します

3. **他のポリシー**: SmolVLAやDiffusion Policyなど、他のポリシーも試してみる
4. **マルチタスク学習**: 複数のタスクを1つのモデルで学習する

## 開発者向けの追加情報

### よくある問題パターンのまとめ

このガイドで説明されている問題パターンは、以下のように体系的に整理されています：

1. **カメラ関連の問題**:
   - FOURCC設定の問題
   - 解像度/FPS設定の問題
   - カメラリソースの解放問題
   - カメラIDの変更
   - macOS固有の問題
   - 設定変更後の読み取り失敗

2. **トレーニング関連の問題**:
   - OpenMPエラー（macOS）
   - FFmpegライブラリエラー
   - GPUメモリ不足
   - トレーニング速度の問題
   - 出力ディレクトリの競合
   - エピソード終了時の自動停止

3. **ロボット関連の問題**:
   - 電圧エラー
   - 通信エラー
   - アームの不安定な動作

### コードの改善履歴

このガイドで説明されている機能は、以下の改善が実装されています：

- ✅ カメラ設定変更後の自動リセット機能
- ✅ トレーニング出力ディレクトリの自動名前更新
- ✅ Ctrl+Cでの自動チェックポイント保存
- ✅ エピソード終了時の自動停止
- ✅ 軽量チェックポイント機能（`save_freq_minor`）

### 開発環境のセットアップ

新しい開発者が参加する場合、以下のコマンドで開発環境をセットアップできます：

```bash
# リポジトリのクローン
git clone <repository-url>
cd lerobot

# 依存関係のインストール
uv sync --extra dev --extra test

# 開発モードでインストール
uv pip install -e .

# テストの実行
pytest tests/<area> -m "not slow"
```
